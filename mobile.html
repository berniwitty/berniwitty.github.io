GRPO 与 OPD 缺少等算力下的直接对照。本项目面向数学推理任务，在同一份训练集（DAPO-Math-17K）与同一评测口径下补上该对照，并进一步回答蒸馏路线下教师选择的依据。GRPO and OPD lacked a direct comparison at matched compute. This project supplies one for math reasoning under a single training set (DAPO-Math-17K) and one evaluation protocol, and further answers how to choose a distillation teacher.

基于 verl 实现 OPD 与 GRPO 双路线，核心差异是监督信号密度Both routes built on verl; the difference is supervision densityOPD 的监督信号是学生自采样序列上逐 token 的反向 KL 值，由教师对数概率算得，以策略梯度回传。GRPO 的监督信号是 math-verify 判定整条回答正误的一个标量。区别在于密度：前者一条回答上千个逐位置信号，后者一个标量摊给全部 token。OPD supervises every token of the student's own sampled sequence with a reverse-KL value from teacher log-probs, back-propagated as a policy gradient; GRPO supplies one math-verify scalar per answer — thousands of per-position signals versus one scalar spread over all tokens.

Active compute aligned by measured GPU utilization; the evaluation protocol is self-built and framework-independent, covering the full GSM8K / MATH-500 / OlympiadBench sets (2,493 problems) with paired significance tests.

要点Point说明Details
监督微调：沙箱真实执行的 6K 条轨迹经过程奖励筛至 3K，构建强化学习起点SFT: 6K sandbox-executed trajectories filtered to 3K by process reward, giving the RL starting point轨迹数据：以 Qwen3-Coder-30B 为教师，在沙箱中真实运行代码、读回输出继续推理，端到端产出 6K 条多轮工具调用轨迹，再用过程奖励模型 ReasonFlux-PRM 打分排序保留 3K 条；以此全参微调 Qwen3-4B-Instruct-2507，得到具备多轮工具调用能力的强化学习起点模型。Trajectory data: with Qwen3-Coder-30B as the teacher, code was really executed in the sandbox and its output read back to continue reasoning, producing 6K multi-turn trajectories end to end; ReasonFlux-PRM scored and ranked them down to 3K, which fully fine-tuned Qwen3-4B-Instruct-2507 into a starting model with multi-turn tool-use ability.
强化学习数据：分层采样使代码题占比由 14% 提至 42%，让工具使用质量进入奖励RL data: stratified sampling lifts code problems from 14% to 42%, putting tool-use quality into the reward推理题库数据：30K 道，由 17.9K 道竞赛数学题、4.9K 道通用数学题、4.3K 道代码题与 3.0K 道科学题混合而成，以避免单一题型使策略收窄到固定解法。训练集数据：依奖励判定方式分层采样 600 道——数学题的奖励只看最终答案是否匹配，模型是否调用工具、代码是否跑通均不进入奖励；代码题的奖励则由沙箱执行单元测试的结果直接决定。代码题在题库中仅占 14%、随机采样下三成批次抽不到，分层提升至 42% 使其稳定进入每步更新。Problem pool: 30K items — 17.9K competition math, 4.9K general math, 4.3K code, 3.0K science — mixed so no single type narrows the policy to one solution pattern. Training set: 600 items stratified by how the reward is judged; math rewards check only the final answer, ignoring whether tools were called, while code rewards come from sandbox unit tests. Code problems are 14% of the pool and missing from three in ten batches under random sampling, so lifting them to 42% keeps them in every update.

Pacman 多智能体对战系统Pacman multi-agent contest

排名 11 / 298Rank 11 / 298
  • 赛制Format2v2 对战，名次按所有参赛队两两对战的胜率排定。2v2 matches, ranked by pairwise win rate against every other team.
  • 高层规划High-level planningPDDL 把局面抽象成符号谓词与目标，在保守进攻、激进进攻、边界巡逻、追击入侵者、位置重排之间切换，依据是风险、比分、携带食物和地图控制。PDDL abstracts the board into predicates and goals, switching between conservative attack, aggressive attack, border patrol, chasing invaders and repositioning, based on risk, score, carried food and map control.
  • 低层执行Low-level executionA* 路径搜索，启发式里加入避开对手危险区、回家路径安全评估和边界约束。A* path search with heuristics for opponent danger zones, safe-return evaluation and border constraints.
  • 兜底策略Fallback规划失败或时间不足时，退回基于得分变化与距离特征的 Q-learning，保证整体稳定。When planning fails or time runs out, a Q-learning policy on score-change and distance features keeps behaviour stable.
  • 多智能体协同Coordination每个智能体把意图、目标、危险等级、已认领的食物和边界站位写进共享信息表，因此不会抢同一份食物，防守位自动分配，还能吃能量豆去救队友。Each agent writes its intent, target, danger level, claimed food and border post into a shared table, so agents never contest the same food, split border defence automatically and rescue teammates with power pellets.

Flatland 多智能体铁路调度系统Flatland multi-agent railway scheduling

排名 14 / 315Rank 14 / 315
  • 评分口径Scoring名次按所有地图、所有列车数量下的按时到达比例与所需时间步排定。Ranked by on-time arrival rate and time steps across all maps and train counts.
  • 调度顺序Scheduling order按每列车距截止时间的时间余量计算紧迫度，余量小的先排。Trains are ordered by slack to their deadlines, the tightest first.
  • 路径规划Path planning安全区间路径规划（SIPP）把搜索状态扩展为「位置 + 方向 + 所在安全时间段」，安全时间段由已规划路径的时间占用表合并空闲区间得到，配曼哈顿距离启发式，避免节点碰撞与对向交换冲突。Safe-Interval Path Planning expands each state into position, direction and safe interval, where intervals come from merging free slots in an occupancy table over planned paths; a Manhattan-distance heuristic avoids node collisions and head-on swaps.
  • 结构约束Structural constraints死胡同轨道只在作为起终点或已被占用时允许进入；先带结构约束规划，失败再放宽约束兜底，在高密度路网里兼顾可解率与搜索效率。Dead-end tracks are entered only as origin, destination or when already occupied; a constrained-first, relaxed-fallback two-stage plan balances solvability against search cost on dense networks.
  • 故障重规划Malfunction handling故障发生时保留所有列车已执行的轨迹前缀，只对受影响的列车做局部重规划，避免全局重算超时和内存爆炸。Executed trajectory prefixes are kept and only affected trains are re-planned locally, avoiding global re-computation timeouts and memory blowups.
