基于强化学习与在线蒸馏的数学推理模型后训练GRPO vs. On-Policy Distillation — Post-Training a Math-Reasoning LLM at Matched Compute

技术栈：RLVR、GRPO、OPD、Reverse KL、verl、vLLM、FSDP、Ray、PyTorchStack: RLVR, GRPO, OPD, Reverse KL, verl, vLLM, FSDP, Ray, PyTorch

GRPO 与 OPD 缺少等算力下的直接对照。本项目面向数学推理任务，在同一份训练集（DAPO-Math-17K）与同一评测口径下补上该对照，并进一步回答蒸馏路线下教师选择的依据。GRPO and OPD lacked a direct comparison at matched compute. This project supplies one for math reasoning under a single training set (DAPO-Math-17K) and one evaluation protocol, and further answers how to choose a distillation teacher.

  • 基于 verl 实现 OPD 与 GRPO 双路线，核心差异是监督信号密度：OPD 的监督信号是学生自采样序列上逐 token 的反向 KL 值，由教师对数概率算得，以策略梯度回传。GRPO 的监督信号是 math-verify 判定整条回答正误的一个标量。区别在于密度：前者一条回答上千个逐位置信号，后者一个标量摊给全部 token。Both routes built on verl; the difference is supervision density: OPD supervises every token of the student's own sampled sequence with a reverse-KL value from teacher log-probs, back-propagated as a policy gradient; GRPO supplies one math-verify scalar per answer — thousands of per-position signals versus one scalar spread over all tokens.
  • 等活跃算力下 OPD 三个基准准确率均高于 GRPO，50 步即超其 250 步终点准确率：准确率相对未训练的学生模型提升 17 至 26 个百分点。活跃算力按实测 GPU 利用率折算对齐；评测协议自建、独立于训练框架，覆盖三个难度递增的数学基准（GSM8K / MATH-500 / Olympiad-Bench）全量测试集共 2493 题，并做配对显著性检验。At matched active compute OPD beats GRPO on all three benchmarks, passing GRPO's 250-step endpoint by step 50: +17 to +26 pts over the untrained student. Active compute aligned by measured GPU utilization; the evaluation protocol is self-built and framework-independent, covering the full GSM8K / MATH-500 / OlympiadBench sets (2,493 problems) with paired significance tests.
  • 同源准确率相近的双教师对照：与学生路径一致者蒸出的学生准确率更高，差距随难度递增：两个教师同出自 Qwen3-4B-Base、自身基准准确率仅相差 2.2 个百分点，区别只在后训练路径：一个跳过 SFT 直接做单域数学强化学习，与学生路径一致；另一个是经多阶段通用后训练的 Qwen3-4B 指令模型。该差距至最难的基准达到统计显著，训练首步两个教师在学生序列上逐 token 对数概率差的均值即相差 1.6 倍，通用后训练的教师离学生的分布更远。Two same-origin teachers of near-equal accuracy: the route-matched one distills better, and the gap grows with difficulty: both come from Qwen3-4B-Base and differ by 2.2 pts on their own benchmarks; one skipped SFT and did single-domain math RL, matching the student's route, the other is the multi-stage post-trained instruct model. The gap reaches significance on the hardest benchmark, and at the first step their mean per-token log-prob gap on student sequences already differs by 1.6x.

面向数学推理的多轮工具调用智能体强化学习训练与评测Multi-Turn Tool-Use Agent for Math Reasoning — Agentic RL Training & Evaluation

技术栈：GRPO、DAPO、RLVR、Agentic RL、SFT、verl、vLLM、Ray、FSDP、PyTorchStack: GRPO, DAPO, RLVR, Agentic RL, SFT, verl, vLLM, Ray, FSDP, PyTorch

面向数学推理构建多轮工具调用智能体的完整后训练流程：基座模型 → 工具调用监督微调 → 强化学习。模型在推理途中自主发出 Python 代码，由沙箱执行后读取输出继续推理，单条轨迹最多 16 轮。Built the full post-training pipeline of a multi-turn tool-use agent for math reasoning: base model, tool-use SFT, then RL. The model emits Python mid-reasoning, a sandbox executes it and the output is read back to continue, up to 16 turns per trajectory.

  • 监督微调：沙箱真实执行的 6K 条轨迹经过程奖励筛至 3K，构建强化学习起点
    轨迹数据：以 Qwen3-Coder-30B 为教师，在沙箱中真实运行代码、读回输出继续推理，端到端产出 6K 条多轮工具调用轨迹，再用过程奖励模型 ReasonFlux-PRM 打分排序保留 3K 条；以此全参微调 Qwen3-4B-Instruct-2507，得到具备多轮工具调用能力的强化学习起点模型。    SFT: 6K sandbox-executed trajectories filtered to 3K by process reward, giving the RL starting point
    Trajectory data: with Qwen3-Coder-30B as the teacher, code was really executed in the sandbox and its output read back to continue reasoning, producing 6K multi-turn trajectories end to end; ReasonFlux-PRM scored and ranked them down to 3K, which fully fine-tuned Qwen3-4B-Instruct-2507 into a starting model with multi-turn tool-use ability.
  • 强化学习数据：分层采样使代码题占比由 14% 提至 42%，让工具使用质量进入奖励
    推理题库数据：30K 道，由 17.9K 道竞赛数学题、4.9K 道通用数学题、4.3K 道代码题与 3.0K 道科学题混合而成，以避免单一题型使策略收窄到固定解法。训练集数据：依奖励判定方式分层采样 600 道——数学题的奖励只看最终答案是否匹配，模型是否调用工具、代码是否跑通均不进入奖励；代码题的奖励则由沙箱执行单元测试的结果直接决定。代码题在题库中仅占 14%、随机采样下三成批次抽不到，分层提升至 42% 使其稳定进入每步更新。    RL data: stratified sampling lifts code problems from 14% to 42%, putting tool-use quality into the reward
    Problem pool: 30K items — 17.9K competition math, 4.9K general math, 4.3K code, 3.0K science — mixed so no single type narrows the policy to one solution pattern. Training set: 600 items stratified by how the reward is judged; math rewards check only the final answer, ignoring whether tools were called, while code rewards come from sandbox unit tests. Code problems are 14% of the pool and missing from three in ten batches under random sampling, so lifting them to 42% keeps them in every update.
  • 评测与成果：AIME 测试集上共提升 16.3 个百分点，训练量仅为全量的 1.4%
    在 AIME2024、AIME2025 各 30 题上评测，每题独立作答 16 次、合计 960 次采样。    Results: +16.3 pts in total on the AIME test sets, using 1.4% of the full training volume
    Evaluated on AIME2024 and AIME2025, 30 problems each, 16 independent runs per problem, 960 samples in total.

  • 基于已规划路径维护轨道节点和区段的时间占用表，合并空闲区间生成安全时间段，在 SIPP 搜索中把状态扩展为“位置 + 方向 + 所在安全时间段”，并用基于曼哈顿距离的启发式引导搜索，避免节点碰撞和对向交换冲突Time-occupancy tables for track nodes and segments are maintained from the planned paths, free intervals are merged into safe windows, and the SIPP search expands states as position + direction + safe interval, guided by a Manhattan-distance heuristic to avoid node collisions and head-on swaps

  • 设计 MCP 重规划兜底模块：故障发生时保留所有列车已执行的轨迹前缀，局部微调受影响列车的剩余行程进行排队等待，避免全局重算超时和内存爆炸Designed an MCP replanning fallback: on a malfunction the executed trajectory prefixes of all trains are kept and only the remaining journey of affected trains is adjusted locally into a queue-and-wait, avoiding global recomputation timeouts and memory blowups
